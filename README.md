# Project Silkworm

An automated pipeline that generates a continuously growing **DPO (Direct Preference Optimization) preference dataset** and uploads it to the Hugging Face Hub.

For each prompt, the same model answers twice under two different system prompts: a thorough expert one (**chosen**) and a terse, superficial one (**rejected**). The quality contrast gives preference pairs without human annotation.

- **Dataset:** [`iPwnds/Project-Silkworm`](https://huggingface.co/datasets/iPwnds/Project-Silkworm) on Hugging Face
- **Website:** [lumenworksco.github.io/-Project-Silkworm](https://lumenworksco.github.io/-Project-Silkworm/)
- **Dataset card:** see [`DATASET_CARD.md`](DATASET_CARD.md)
- **Status at last run:** ~2,870 accepted pairs from ~4,750 generations, across 17 domains

## How it works

```
topics.py ──► sample_prompt() ──► generator.py ──► quality filter ──► data/pending.jsonl
                                  (2 chat calls)                          │
                                                                          ▼ every N examples
                                                   data/dataset.parquet ──► Hugging Face Hub
```

1. `topics.py` samples a topic from 17 domains (science, technology, mathematics, history, philosophy, economics, psychology, health, culture, practical, environment, politics, law, linguistics, literature, astronomy, data science) and builds a prompt.
2. `generator.py` calls the HF Serverless Inference API twice with retries and exponential backoff: once with the expert system prompt (max 512 tokens) and once with the terse one (max 256 tokens).
3. Pairs are discarded if the chosen answer is shorter than `MIN_CHOSEN_LENGTH`, the rejected one is shorter than `MIN_REJECTED_LENGTH`, or the two are identical.
4. Accepted pairs are appended to `data/pending.jsonl`. Every `UPLOAD_EVERY` pairs, `uploader.py` merges them into `data/dataset.parquet` and uploads it. Prompts already in the parquet are skipped.
5. `main.py` shows a live terminal dashboard. Ctrl+C stops cleanly and uploads the final batch.

## Setup

Requires Python 3.10+ and a [Hugging Face access token](https://huggingface.co/settings/tokens) with write access to your target dataset repo.

```bash
git clone https://github.com/lumenworksco/-Project-Silkworm.git Project-Silkworm
cd Project-Silkworm
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # then fill in HF_TOKEN and HF_DATASET_REPO
python main.py
```

## Configuration

Set in `.env` (see `.env.example`):

| Variable | Default | Description |
|---|---|---|
| `HF_TOKEN` | – | Hugging Face token (write access) |
| `HF_DATASET_REPO` | – | Target dataset repo, e.g. `user/my-dataset` |
| `HF_MODEL` | `meta-llama/Llama-3.1-8B-Instruct` | Model used for generation |
| `UPLOAD_EVERY` | `50` | Accepted pairs between uploads |
| `MIN_CHOSEN_LENGTH` | `200` | Minimum characters for a chosen response |
| `MIN_REJECTED_LENGTH` | `30` | Minimum characters for a rejected response |
| `REQUEST_DELAY` | `1.5` | Seconds to sleep between API calls |

## Using the dataset

```python
from datasets import load_dataset

ds = load_dataset("iPwnds/Project-Silkworm", split="train")
```

Columns: `prompt`, `chosen`, `rejected`, `topic`, `timestamp`. The format works with [TRL](https://github.com/huggingface/trl)'s `DPOTrainer`.

## Limitations

- Pairs are synthetic. "Chosen" means "answered under the expert prompt", not human-verified correctness, so responses may contain factual errors.
- The rejected side is deliberately low quality, so a model trained on it learns mostly a length and effort preference.
- Generated by a single 8B model, so it inherits that model's biases and gaps.
